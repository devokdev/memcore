FAQ

Frequently asked questions.

What makes MemCore different from plain vector stores?

Plain vector stores blindly hoard conversation text until prompt windows blow up. MemCore adds MemGC risk-aware garbage collection with utility scoring, deduplication, and code AST verification. It guarantees that critical database contracts and security policies can never be pruned, while saving up to 92% in token overhead.

Does any proprietary code leave my computer?

Zero bytes. MemCore binds exclusively to 127.0.0.1:8000. All FTS5 keyword indexing, vector embeddings, and AST verifications execute completely on-device.

Do I need an OpenAI or third-party API key?

No API key required. MemCore works out of the box with zero external dependencies. SQLite FTS5 handles keyword retrieval and local embedding engines run on your CPU/GPU.

What is the Zero Protected Memory Loss guarantee?

Memories tagged with is_protected=True (such as database migration invariants, authentication requirements, or user rules) are assigned a Risk score R = 1.0. The MemGC optimizer enforces a mathematical invariant that prevents deletion or destructive compaction of these records regardless of age.

How is MemCore licensed?

Apache-2.0. Completely free, open source, and modifiable for commercial or private use.
